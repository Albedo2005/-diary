# 功能清单与可行性评估

这份文档用于在动手前把范围谈清楚。**难度分级只描述"实现难度"，不等于"价值"** ——
有些简单功能价值极高（如自动保存），有些困难功能价值有限（如天气自动记录）。

## 难度分级定义

| 级别 | 含义 | 判断依据 |
|---|---|---|
| ★ | 简单 | 有成熟库或平台能力，照着文档写即可 |
| ★★ | 中等 | 逻辑清晰但细节多，需要认真测试 |
| ★★★ | 困难 | 有真实工程风险，或必须处理数据安全/完整性 |
| — | 非技术 | 主要是流程、成本或运营问题，不是编程难度 |

同理，"可行性"回答的是**能不能做出来**，不是"值不值得做"。

## P0：第一版必须有（六项，做完即是可用产品）

### 1. 设置主密码 / 解锁

- **难度**：★★
- **可行性**：高。SQLCipher 自带密钥验证，不需要自己实现密码校验
- **卡点**：盐值与 KDF 参数必须持久化；解锁失败时不能泄漏"密码错在哪一位"
- **工作量**：1~2 人日

### 2. 密码输错锁定（5 次 / 10 分钟 / 提示）

- **难度**：★★
- **可行性**：高，纯逻辑
- **卡点**：锁定状态**必须放在加密库之外**（用户没解锁时也要读写它）；
  必须持久化到文件，否则重启应用即可绕过；系统时间被回拨怎么办（记录单调时间戳）
- **工作量**：1 人日

### 3. 无干扰 Markdown 编辑器

- **难度**：★★（基础版）→ ★★★（完整版）
- **可行性**：高
- **卡点**：这一项的范围弹性极大，是**最容易低估工期的功能**。区别在于：
  - 基础版：纯文本输入 + 自动保存 + 简单 Markdown 语法高亮 = 几天
  - 完整版：实时预览、表格、任务列表、图片拖拽、粘贴上传、撤销栈、
    输入法中文组字不打断 = 数周
- **关键提醒**：中文输入法组字（IME composition）期间不能触发自动保存，
  否则会把输入到一半的拼音存进数据库。这是中文应用的经典坑
- **工作量**：基础版 3~5 人日；完整版 15~25 人日

### 4. 一天一篇 + 自动保存

- **难度**：★
- **可行性**：高。唯一约束在数据库层保证（已验证）
- **卡点**：自动保存要防抖（输入停止约 1 秒再落库）；`entry_date` 与
  `created_at` 必须分离，否则补写昨天的日记会污染时间事实
- **工作量**：1~2 人日

### 5. 日历主界面

- **难度**：★★
- **可行性**：高
- **卡点**：月份切换、当天高亮、有日记的日子做标记（需要一个聚合查询）；
  时区与"今天"的判定要以本地日期为准，不能用 UTC
- **工作量**：3~4 人日

### 6. 中文全文搜索

- **难度**：★★★（唯一一个真正的技术难点）
- **可行性**：高，**方案已定案并实测通过**
- **卡点**：已解决。详见 `schema-decisions.md` 与 `probe-findings.md`：
  - 采用 **jieba 预分词**（实测 7 个查询词全中，索引比 trigram 小 71%）
  - 否决 **trigram**：2 字词（火锅/开心/日落）是中文日记高频词，全部搜不到
  - 索引用 **contentless + `contentless_delete=1`**，免疫文本漂移导致的索引损坏
  - 建**两张索引**：jieba 词索引（精确）+ 单字索引（兜底）。
    实测「牛肉」只能被字索引命中，证明双索index 有必要
  - 结果高亮在**原文**上做子串匹配（FTS5 的 highlight 输出含分词空格，排版破碎）
- **剩余工作**：把已验证的结构落成正式代码
- **工作量**：2~3 人日（方案已定，只剩实现）

### 7. 自动备份

- **难度**：★★
- **可行性**：高
- **卡点**：备份的是**加密库文件**，直接文件复制即可，不需要解密；
  需处理"备份时数据库正在被写入"（用 SQLite 的在线备份 API，不要裸复制文件）；
  需要保留策略（保留最近 N 份 + 每月归档）
- **工作量**：2 人日

**P0 合计：约 15~25 人日**（搜索按 jieba 方案计）

## P1：第二版，明显提升价值

### 8. 标签系统

- **难度**：★★
- **可行性**：高
- **卡点**：标签重命名/合并时的一致性；删除标签不能删日记（外键级联方向别搞反）
- **工作量**：3 人日

### 9. 心情标记

- **难度**：★
- **可行性**：高
- **卡点**：几乎没有。真正的价值在后面的统计可视化
- **工作量**：1 人日

### 10. 图片附件

- **难度**：★★（不加密）→ ★★★（若要加密）
- **可行性**：高
- **卡点**：数据库只存**相对路径**（绝对路径换电脑就失效）；
  图片渲染路径要经 Rust 侧做安全校验，防止路径穿越；
  孤儿文件回收（删日记后附件要不要删）
- **已定决策**：不加密。风险已知（图片常比正文更敏感，且会被云同步带走）
- **工作量**：3~5 人日

### 11. 导出（Markdown / HTML / PDF）

- **难度**：★（Markdown）→ ★★（HTML）→ ★★★（PDF）
- **可行性**：高
- **卡点**：PDF 需要一个渲染引擎，体积和排版质量都要权衡
- **建议**：先做 Markdown 导出（极简单、可迁移性最好），PDF 延后
- **工作量**：Markdown 1 人日；HTML 2 人日；PDF 4~6 人日

### 12. 修改主密码

- **难度**：★★★
- **可行性**：高，但**必须极其小心**
- **卡点**：改密码 = 更换数据库密钥 = 全库重新加密。这是最容易造成
  **数据永久损坏**的功能，没有之一
- **必须的做法**：先导出到临时文件 → 用新密码打开验证可读 → 再原子替换原文件；
  **绝不能原地改密钥**。任何一步失败都必须保留原库完好
- **工作量**：2~3 人日（其中大部分是测试与故障演练）

### 13. 连续写作天数 / 统计

- **难度**：★★
- **可行性**：高
- **卡点**："连续天数"的判定规则（昨天没写但今天写了，算不算断？）、跨时区
- **工作量**：2~3 人日

## 非技术事项（不是编程难度，但会决定项目能否交付）

| 事项 | 说明 |
|---|---|
| **代码签名证书** | 不签名则 Windows SmartScreen 会警告"未知发布者"。个人证书约几百到几千元/年。**建议开发期跳过，正式分发前再买** |
| **安装包制作** | Tauri 内置 NSIS/MSI 打包，不难；难的是升级不丢数据 |
| **自动更新的托管** | 需要一个用户能访问的下载地址，国内网络环境下要考虑可达性 |
| **多用户使用** | 当前设计是单用户单库。若要支持多用户/多日记本，数据模型要改 |

## 风险评估：整个项目的可执行概率

### 好消息：没有技术性拦路虎

所有 ★★★ 项目都是**已知的工程问题**，不是研究问题。中文分词的三个候选方案
都验证可行，只是取舍不同。**不存在"做不出来"的功能。**

### 真正的风险不在技术，而在这三件事

**风险 1（最高）：范围失控。**
日记软件的完整形态接近 Obsidian，那是几十人年的产品。这个项目要做成，
靠的不是能力，而是**敢砍功能**。P0 之外的每一项都会推迟可用时间。

**风险 2：持久性。** 一个人业余时间开发 + 维护一个桌面应用，
最大的威胁是几周后热度下降。**对策：先做出能自己每天用的最小版本**，
用起来之后再慢慢加功能 —— 这样开发动力来自使用需求，而不是"完成项目"。

**风险 3：数据事故。** 唯一会让用户（也就是你自己）彻底放弃的，
是丢日记。所以自动备份属于 P0，且密码修改这类高风险功能必须最后做。

### 分期可执行性判断

| 阶段 | 内容 | 工作量 | 可执行概率 |
|---|---|---|---|
| 技术验证 | SQLCipher / FTS5 / 中文分词 | 已完成 | ✅ 已验证 |
| 阶段 1 | P0 第 1~5 项（不含搜索与备份） | 8~14 人日 | 高 |
| 阶段 2 | P0 第 6~7 项（搜索 + 备份） | 5~7 人日 | 高（需先定分词方案） |
| 阶段 3 | P1 全部 | 12~18 人日 | 中高 |
| 阶段 4 | P2 按需挑选 | 视选择 | 中 |

**结论：做出一个"能自己每天用"的日记软件，可执行概率很高（约 20~30 人日）。
做成一个"功能完整、能给别人用"的产品，概率中等，主要取决于能否克制范围扩张。**

## 技术验证结论对工期的影响

原估算中"搜索"一项是最大不确定性（3~5 人日且可能返工）。现在**方案已验证定案**，
降为 2~3 人日的纯实现工作。整体风险显著下降：

| 项目 | 验证前 | 验证后 |
|---|---|---|
| 中文搜索 | 高风险，可能返工 | 低风险，结构已定 |
| 加密存储 | 未验证 | 已验证（SQLCipher 静态编译 + 错误密码拒绝） |
| KDF 参数 | 未知 | 已实测（512 MiB / 3 轮 = 792 ms） |
| 剩余未知 | — | 仅剩 IME 组字冲突、备份一致性等实现细节 |
