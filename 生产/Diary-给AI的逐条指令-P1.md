## 开工前的四条兜底纪律（比指令本身更重要，别跳）

这份指令能保证"AI 知道该写什么"，但**保证不了"AI 写得对、你没贴错"**。
真正让制作过程不出问题的是下面这四条，每一条都不能省。

### ① 每个功能 = 一个 git 提交（后悔药你已经有了，把规矩定死就行）

这个项目**已经是 git 仓库**（`D:\Users\Lenovo\Desktop\Diary\.git`，已有 8 次提交），
你也在按功能提交。所以"后悔药"这一条**不是缺口，是纪律**——因为 **git 只保护"提交过"的内容**：
只要 AI 改完你还没 commit，那部分照样没有退路。

- **开工前**：先跑 `git status`，必须是 "nothing to commit, working tree clean"。
  如果有一堆未提交的改动，先 `git add -A && git commit -m "chore: 功能N 开工前的基线"`。
  否则出问题时你分不清"哪些是 AI 改的、哪些是我自己原来留着的"。
- **验收通过后**：立刻 `git add -A && git commit -m "feat: 功能N · 一句话描述"`。
  **一个功能一个提交，别攒着**——攒着就失去了"精确回到上一个好状态"的能力。
  提交信息沿用你现在的风格（`feat:` / `fix:` / `docs:`）。
- **改坏了怎么回滚**：
  - 还没提交 → `git checkout -- .`（丢弃本次全部改动，回到上次提交）
  - 已提交但发现不对 → `git revert <那个提交的哈希>`（生成一个反向提交，安全、不删历史）
  - 想把手里的改动先挪开再回滚 → `git stash`（之后再 `git stash pop` 取回来）

### ② 每做完一个功能，必须"能跑 + 人点一遍"才算完

AI 在对话框里**没法真的运行你的程序**，它说"自检通过"是纸上谈兵，不算数。

- 改完代码后，跑 `pnpm tauri dev` 把应用起起来。
- **起不来 / 报错** → 代码有问题，把报错原样贴回给 AI 让它修，**不要带病继续下一个功能**。
- **起得来** → 你自己照着那条指令的"验收"清单一项项点一遍，全过才算做完。

### ③ 大改动，让另一个 AI 复审 diff 再贴

写代码的 AI 写完后、你粘贴前，把它给的改动贴给**另一个** AI 复审（我，或者你用的 Kimi 都行——
关键是**别让同一个 AI 既写又审**，它看不出自己的错）。
通读过这个项目的 AI 能看出它有没有违背铁律（比如私自写 `content_md != ''`、漏改 `lib.rs`、动了 `content_md` 原文）。
分工：**一个 AI 负责写，另一个负责把关，你负责搬运 + 跑起来验收**。

### ④ 你自己动手改文件时，别用 PowerShell 做文本替换

本项目出过一次中文乱码事故：用 PowerShell 批量替换 `.vue/.rs/.ts` 里的文本会破坏 UTF-8 编码，中文全变乱码。
要改就用记事本 / VS Code / Trae 这类编辑器直接改。
（如果你全程只是"复制 AI 给的代码 → 粘到编辑器"，这条自动满足。）

````
【项目背景 · 本次对话必读】

项目：本地加密日记本。技术栈 Tauri 2（Rust 后端）+ Vue 3 + TypeScript 前端 + SQLCipher 加密数据库。

目录与分层（改代码前先记住这个分工）：
- app/src/**                    前端（Vue 3 + TS）
- app/src/api/index.ts          前端调后端的唯一出口，每个后端命令对应一个封装函数
- app/src-tauri/src/commands.rs 命令层。只做参数校验 + 解锁守门，业务逻辑一律甩给 db.rs
- app/src-tauri/src/db.rs       数据层。所有 SQL 都写在这里
- app/src-tauri/src/schema.rs   建表语句 + SCHEMA_VERSION
- app/src-tauri/src/crypto.rs   密钥派生、锁定期
- app/src-tauri/src/lib.rs      启动 + 命令白名单（generate_handler!）

最重要的一条工作方式（先看这个）：
- 你看不到我项目里的真实代码，绝对不要凭记忆瞎写现有函数。
  动手前如果需要参考某个文件/函数的当前实现，直接开口：
  "请贴 XX 文件的 XX 函数"，我贴给你之后你再继续写。
  宁可多问几次，也不要靠猜。

必须遵守的铁律：
1. 新增一个后端命令必须同步改四处，漏一处前端就调不通：
   db.rs 加实现方法 → commands.rs 加 #[tauri::command] 函数 → lib.rs 的 generate_handler! 里登记 → api/index.ts 加封装。
   （命令若不涉及数据库、只读写库外文件，则没有 db.rs 那一步 —— 这种例外只会在指令里明确点名。）
2. 凡是要碰数据的命令，必须用 with_vault(&state, |v| ...) 包住（未解锁统一拒绝）。
   例外只有：app_status / estimate_kdf_ms / initialize_vault / unlock_vault / lock_vault，
   以及**不碰库、只读写库外文件**的命令（本项目**现在没有这类命令** —— 唯一一组
   get_window_mode / set_window_mode 已随指令 12 一起作废，见上面的作废说明）。
   判断标准是"这个命令在未解锁时是否需要能用"——需要，就不能走 with_vault。
3. 前端永不接触密钥、不传 SQL，只传业务参数（日期、文本、id）。前端组件不许直接 invoke，一律走 api/index.ts。
4. "这天写过没"只有一个判定来源：db::has_content_sql()（SQL 侧）和 db::has_content()（Rust 侧）。
   禁止自己写 content_md != '' 之类的判定。
5. 一天一篇靠数据库 UNIQUE(entry_date) 保证。写库统一用 INSERT ... ON CONFLICT(entry_date) DO UPDATE，禁止"先查再插"。
6. 错误必须带稳定的 kind 字段（前端按 kind 分支，不解析 message 文本）。
7. 不要动：entry.content_md 永远是 Markdown 原文；entry.notebook_id 字段必须保留。

- 只改本指令里列出的文件，不要顺手重构、格式化其他地方。

# 【指令 2】心情标记

**前置依赖：无**

````
【任务】心情标记（每天一个心情）

背景：数据库 entry 表已经有 mood 字段（INTEGER，可空），但没有代码在用。
约定取值：1=很差 2=较差 3=一般 4=较好 5=很好，NULL=未标记。

核心约束：不能让 mood 变成"非空判定"的一部分。
现有系统的核心规则是"content_md 去空白后非空 = 写过"。
如果允许在一篇空日记上标心情，就会出现"有心情但没内容"的行，与"打开 ≠ 写过"这条铁律直接冲突。
所以 mood 必须并进 save_entry，不许单独开命令。

要改的文件与做法：

1) db.rs
   - save_entry 加参数：mood: Option<i64>
   - INSERT ... ON CONFLICT(entry_date) DO UPDATE 里同步写 mood 列
   - 硬规则：mood 只在"这篇会被收录（has_content() 为真）"时才写入；
     无内容时不落库，沿用现有的"空则不落库 / 删空行"逻辑。
   - 校验 mood 只能是 1..=5 或 None，其他值返回 validation 错误。
   - 检查 open_entry 以及所有构造 Entry 的查询是否已取出 mood 列并映射进 Entry.mood；没有就补上。

2) commands.rs —— save_entry 加 mood: Option<i64> 参数，透传给 db.rs（仍走 with_vault）。

3) api/index.ts —— saveEntry 加 mood 参数；确认 Entry 类型已含 mood。

4) EditorPane.vue
   - 标题行右侧加 5 个 emoji 按钮表示心情，当前心情高亮。
   - 点选后立即触发一次保存（把当前内容 + mood 一起写）。
   - 再点同一个 → 取消（传 null）。
   - 内容为空时心情条置灰或不显示。

5) CalendarPanel.vue
   - 有心情的日期在格子上显示对应的小 emoji。
   - 这是新增的"第三种标记"，只在有 mood 时显示。不要改动已有的 written / today 逻辑和样式。
   - 如果后端现有的"哪些天写过"接口只返回日期集合，就新增一个返回 日期→mood 映射 的方法和命令。

验收：
[ ] 写内容后点 🥰 → 保存 → 重开这天，心情仍是 🥰
[ ] 把内容全部删空 → 心情随记录一起消失，不残留"有心情没内容"的行
[ ] 日历上该天显示心情 emoji
[ ] 空内容的日期依然不被标记为"写过"（关键回归点）

**为什么"只有回车算数"而不是"打满 4 位自动生效"**：后者看起来更快，但打错一位就没法改了 ——
第 4 个数字一落就跳走，用户想改只能重来。回车把"我想好了"和"我还在打"分开。

**为什么输入框里不实时 clamp**：打 `1800` 的过程要经过 `1`、`18`、`180` ——
每一步都不在范围内，实时夹的话第一个字符就被弹成 `1949`，根本打不进去。
