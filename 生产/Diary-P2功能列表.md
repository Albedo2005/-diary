## 三、详细设计

### 3.1 P2-3 正文富文本化（类 Word 工具栏）★本轮重点

**先说清三层，之前没讲明白（"路线 A / B"这个说法作废）**：

| 层            | 做什么                       | 字本身变不变                 |
| ------------ | ------------------------- | ---------------------- |
| 换外衣          | 换字体、限行宽、加"纸面"             | ❌ 不变，还是你打的那些字          |
| 段落化          | 显示时把"连续两个换行"变成"段落空隙"      | ❌ 不变                   |
| **富文本（你要的）** | **每个字可以有自己的样子**（粗体、字号、字体） | ✅ **变** —— 除了字，还多了"格式" |

**你要的是第三层。** 它比前两层都深：前两层只动"显示"，第三层动的是**存的东西本身**。

**长什么样**（已给你看过效果图）：

- **顶部那一行**（原"标题"那一行）＝ 工具栏：  
  `字体 ▾ ｜ 字号 ▾ ｜ B ｜ I ｜ U ｜ S ｜ 清除格式` ；**心情 5 档挪到这一行最右边**。
- 选中文字 → 点 `B` 就变粗；光标落在粗体上时，`B` 会显示"按下"状态。
- **字体**给 4 项：宋体 / 黑体 / 楷体 / 系统默认。
- **字号**给 5 档：12 / 14 / 16 / 18 / 20（**用数字，不用"四号/小四"** —— 数字直观、不用查表）。
- **不做的**：颜色、对齐、缩进、项目符号。理由：日记不需要花花绿绿，**颜色还会跟"心情色"抢戏**。

**⚠️ 它打破了这个项目最硬的一条铁律**：「**正文永远只有用户打的字**」。  
以后 `entry_body` 里除了你打的字，还有**你看不见的格式标记**。连带四条：

| # | 连带        | 怎么办                             |
| - | --------- | ------------------------------- |
| 1 | 搜索命中位置的计算 | 要按"可见文字"算，不能按存储原文算（否则高亮会错位）     |
| 2 | 导出（**两处**） | 都会掉格式 ⇒ **新版 HTML 导出 ＋ 已有的 Markdown 导出**，**两处都要改**（见第五节）。⛔ 别只改一处 |
| 3 | 统计口径      | 字数统计要**只数文字、不数标记** —— ⚠️ **第 2 批第 0 步已把"数字数"收成零件**（2026-09-23 拍板）。⚠️ **2026-09-28 核过代码：那个零件现在是"空壳"** —— `utils/text.ts::visibleText()` 里就一句 `return raw;`（恒等函数）。所以 P2-3 要做的**不是"改它内部一处参数"，是"把它真正实现出来"**（写一个"剥掉格式标记、只留文字"的函数）。这是本件里**唯一一处要回头改老东西**的地方，✅ 已写进指令【P2-3】第二节 |
| 4 | 锁定态显示什么   | 建议：锁定后**显示排版好的样子（只读）**，比现在更好看   |

**⚠️ 还有一条铁律要继续守**（拿旧伤换来的）：  
**编辑态永远以原文为准，绝不做"把显示结果写回原文"**。  
（P0 第 10 项原叫「阅读模式」，`1.3` 撤掉的理由就是"渲染会吃掉用户手动排的换行和空格"。）

**⚠️ "存成什么格式"是个什么问题（用大白话讲，你本轮问的）**

计算机**只会存"字"，它不会在字上加粗**。所以你想让"下雨"这两个字是粗的，  
就必须用**某种写法**，把"加粗"这件事也写成字。三种写法：

| 写法                      | 数据库里实际躺着的东西                        | 特点                             |
| ----------------------- | ---------------------------------- | ------------------------------ |
| **① 符号标记**（Markdown 那种） | `今天**下雨**了`                        | 还是纯文字、肉眼能读懂；但搜索"下雨"时要跳过那两个 `*` |
| **② HTML 标签**（网页的写法）    | `今天<b>下雨</b>了`                     | 浏览器直接认，导出 HTML 最顺；符号比 ① 多      |
| **③ 结构化文档**（Word 那种）    | `[{"字":"今天"},{"字":"下雨","粗":true}]` | 最严谨、搜索统计最省事；但数据库里完全看不懂，迁移最麻烦   |

**这个决定什么时候做？** ✅ **2026-09-28 已定案 ＝ ② HTML 标签**（`今天<b>下雨</b>了`）。  
拍板理由：**紧随其后的第 6 批就是 P2-8（HTML 导出）** —— 正文里存的本就是 HTML，
导出时几乎白送；而成对闭合的 `<b>…</b>` 比 `**…**` 好判边界（`**` 在中文里容易和别的符号搅在一起）。
代价如实记着：一旦有日记按 HTML 存进去，以后想换成 ① 或 ③ 就得**把所有老日记重新翻译一遍**。

⚠️ **手打的 `<` `>` 怎么办**：这一条**顺带定死**（属于同一次拍板）——
正文里**用户自己打的 `<` 和 `>` 一律原样存、原样显示**（就是"小于号""大于号"两个字面符号），
⛔ **不引入 HTML 实体转义那一套**。理由：这是私人日记本，不是网页编辑器；
让 `2 < 3` 突然显示成别的东西，比"少一个加粗"严重得多。做法上靠**白名单**：
只认我们自己写进去的那 8 个标签（见指令【P2-3】第二节），其余一律当普通文字显示。

**老数据怎么办**：现有的日记是纯文本，**必须一个字不少地照常打开**（迁移只加一层"当纯文本渲染"，不改原字）。

   - ⛔ **错误做法**：把"没写"写死成一个浅灰 ⇒ **深色主题下它就是一个个亮窟窿**。  
     （我给的第一版对比图正是栽在这：两行都硬编码浅色，在你深色界面上渲染出来**全是白的**，等于没改。）
   - ✅ **正确做法**：**新增 5 个主题色号变量**（`--heat-0` ～ `--heat-4`），**深浅两套各 5 个**，  
     组件里只引用变量。深色主题下"由浅到深"读作"**由暗到亮**"。
   - ⚠️ **"没写"的灰必须比"写了"最浅那档更弱**（不能盖过它，否则本末倒置）。  
     ⚠️ 这条在**深色主题下最容易破**：`--heat-0` 必须比 `--heat-1` **更暗**。
   - ✅ **"写了"用绿色系由浅到深**（你参考图的观感：`#C0DD97 → #97C459 → #639922 → #3B6D11`）。

**✅ 分档怎么分（定稿，见指令）**：**按"分位数"而不是固定字数阈值**。  
固定阈值（比如 100/300/600 字）会让"每天写 2000 字的人"永远顶格、"每天写 50 字的人"永远最低，  
**图就变成一片纯色、失去分辨力**；分位数保证颜色分布永远均匀。  
⚠️ 代价：颜色只说明**相对**多少 ⇒ **悬停必须给出绝对字数**，别只靠颜色。  
⚠️ 数据太少时（写过不足 8 天）**不分档**，一律最浅 —— 那时候"相对"没有意义，  
而且会给出"你今天是最低档"这种**不该有的暗示**。

**其他细节**：

- **第一年怎么办**：数据不满一年时，左边**留空**，不要拉长格子充数。
- **和"连续天数"的关系**：连续天数是精确数字，热力图是它的视觉版，两个并排才完整。

**⚠️ 五条最要紧的实现判断（细节见指令文档【P2-22】）**：

1. **用 `v-show` 折叠，不用 `v-if`** —— `v-if` 会**卸载组件**（丢月份状态、丢已拉取的标签、展开时重跑一次 IPC）。  
   ✅ 之所以能放心用 `v-show`：**核对过 `CalendarPanel` 里没有任何尺寸测量**（全文唯一的 `nextTick` 后面只做 `focus()`）。  
   ⚠️ **这条差异是选型关键，别照抄到别的组件上** —— `EditorPane` 就**靠量 `scrollWidth`** 判断"缩略图装不装得下"，  
   那边 `display: none` 会让尺寸变 0、展开后算错。
2. **状态存 `localStorage`、不存加密库** —— 存库要**等解锁**，而布局在解锁前就得定 ⇒ 必然"先展开、解锁完再收起"的闪烁；

   （兜底方向＝**展开**：只有精确 `"1"` 才算折叠，其余一切含异常都算展开。）
3. **限宽用 `padding`，不用 `max-width`** —— `.editor` 本来就有 `padding: 20px 28px 24px`，  
   把它换成自适应即可 ⇒ **日期行和正文自动对齐**；若给 `textarea` 加 `max-width` + `margin: auto`，  
   正文居中了但**日期会留在屏幕最左**，两处错位。
4. **图标固定不变、状态靠悬停提示说** —— 项目里已有同款先例（`EditorPane` 的附件条折叠按钮 `.shot-toggle`：  
   字符图标 ＋ `title` 随状态变）；图标变会让人以为"这是个新按钮"。

   "面板"这个形状在 Unicode 里**没有字形稳定的候选**。
5. ⚠️ **连带适配：折叠后要重量一次"缩略图装不装得下"** —— "装不装得下"是**量出来的**（`scrollWidth > clientWidth`），  
   而它的自动触发时机**只有 `window` resize**；**折叠日历不改窗口尺寸**（只改内部布局）⇒ 状态会停在旧值。  
   走 **展开 → 折叠** 时多一个没用的"展开"按钮（轻）；走 **折叠 → 展开** 时**图被裁掉却没有展开按钮**（重）。  
   ✅ 解法 = 一行 `watch(() => props.wide, () => void nextTick(measureStrip))`。
