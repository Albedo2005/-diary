## 三条通用规矩（每批都照这个走）

1. **验收对象必须是发布件本身**（`发布\日记.exe`），不是 `target\release\app.exe` ——
   两者**字节数可能不同** ⇒ 验过的那个必须等于用户拿到的那个。
   脚本用 `DIARY_EXE` 环境变量可以覆盖，默认就取发布件。
2. **每一版新脚本都是从上一版整份拷过来、再加一组**（不是重写）。
   这样"上一版验过的那些"每一版都在被复跑 ——
   `3.13` 的 116 条 → `3.14` 163 条 → `3.15` 201 条，只增不减。
   ⚠️ 换版本时**必须同步改四处**：`ROOT`（一次性数据目录）／`PORT`（每版都换，别撞）／
   `EXPECT_VERSION`／头部注释。
3. **⚠️ 体积数字读不出改了什么** —— 已经出现三次「与上一版一字不差但内容变了」
   （`3.13`→`3.14` 是 15,940,096→15,970,304；`3.14`→`3.15` 两次都是 15,970,304）。
   ⇒ **只认 sha256**。
4. ⭐ **收工时把日志也挪进来、用中文命名**（用户 2026-09-29 指示：「把这些也扔进生产吧，用中文标清楚」）。
   跑验收 / 测试 / 出包时，脚本会把日志落在仓库根（`_*.log`）或 `_ui-verify-*/` 里 ——
   **它们不该散在根目录**，跑完就归到本文件夹，命名照这四类：
   `验收结果-第N轮-<条数><结论>.log`（**失败的那几轮也留着**，那是证据）／
   `冒烟结果-<结论>.log` ／ `全量测试结果-<结论>.log` ／ `出包结果-….log` ＋ `出包原始输出-….log`。
   ⚠️ **`*.log` 在 `.gitignore` 里是全局忽略的** ⇒ 这些日志**只在本地、不进版本库**
   （用户已明确「不用」为它们开例外）；仓库里能进版本库的是**脚本 ＋ 截图 ＋ README**。
   ⚠️ PowerShell `*>` 落盘的是 **UTF-16LE**，归档时顺手转成 UTF-8（`iconv -f UTF-16LE` 或 Python `decode("utf-16")`）。

## ⚠️ 开跑前先做两件事（不做会得到一片假红）

- **关掉正在运行的日记**：残留的本应用 WebView2 进程会让调试端口**静默失效**
  （症状是连不上，不是报错）。脚本里已带 `killLeftovers()`。
- **清两样东西**：① 一次性数据目录（留着旧库 ⇒ 开屏走"解锁"、成片假红）；
  ② **`localStorage`** —— 它**不在**数据目录里（活在 WebView 用户数据目录），
  光删数据目录清不掉它，上一轮的界面偏好会让这一轮的"开局前提"全错。
