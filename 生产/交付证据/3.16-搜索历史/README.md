## 一、这一件是什么

**P2 的最后两件，一件一记、同记 `3.16`。**

### ① 【P2-20】搜索历史

**改之前**：搜过的词，**下次还得重打一遍**（本项目只能键盘操作，没有鼠标划选）。

**改之后**：搜过的词**按最近在前**记下来，显示成搜索框正下方一排**可点的胶囊**，
点一下就再搜一次；旁边一个「清空」。

⭐ **两个"要猜的都问了用户"**（**铁律当场生效**）：

- **让位规则** ⇒ 用户选「**搜过就让位**」—— 一旦搜过（**哪怕 0 条**）整块历史收起，
  **点输入框的 × 清掉查询后才回来**；
- **位置** ⇒ 用户选「**紧贴搜索框正下方**」（搜索框 → 搜索历史 → 状态提示 → 结果列表）。

⭐ **历史住加密库、不住 `localStorage`**：键 `search_history`（`app_setting` 表），
值是 **JSON 数组字符串** ⇒ **零建表、零迁移、不动 `SCHEMA_VERSION`**。
理由：**搜过的词和日记一样是隐私**（"我在找什么"本身就敏感）。

⭐ **四条数据规则全在后端一处**（`db::push_search_history`）：

| 规则 | 说明 |
|---|---|
| 去重 | 再搜同一个词 ⇒ **挪到最前**，不新增 |
| 上限 | **20 条**，超了丢最旧的 |
| 不收 | **空白** 与 **超长（>50 字）** 直接丢 |
| 兜底 | 值坏掉（不是 JSON / 不是数组）⇒ **静默当没历史**，⛔ 不报错、⛔ 不挡搜索 |

### ② 【P2-2 追加】启动画面至少停 1 秒

**改之前**：冷启动 300~400ms，启动画面**一闪而过**，看着像"没反应"。

**改之后**：**至少停 1 秒**。⭐ **关键是"至少"两个字** ——
等的是 `Math.max(0, 1000 - performance.now())`，**把已经耗掉的时间抵扣掉**；
⛔ **不是 `setTimeout(…, 1000)`**（那样慢机器上等的是"1 秒 ＋ 本来耗时"）。
图标一颗**纯 CSS 呼吸**（透明度 0.55~1、1.4s、无限循环），
并**尊重系统的「减弱动态效果」**。

**改动面**：

| 文件 | 改什么 |
|---|---|
| `app/src-tauri/src/db.rs` | 常量 `MAX_SEARCH_HISTORY` / `MAX_SEARCH_QUERY_CHARS` ＋ 键 `SEARCH_HISTORY` ＋ 4 个方法 ＋ **8 条单测** |
| `app/src-tauri/src/commands.rs` | `get_search_history` / `push_search_history` / `clear_search_history`（都走 `with_vault`） |
| `app/src-tauri/src/lib.rs` | 登记那三条命令（**漏了不报编译错**） |
| `app/src/api/index.ts` | 3 个封装 |
| `app/src/components/SearchPanel.vue` | 历史区（模板 ＋ 样式 ＋ `loadHistory`/`remember`/`pick`/`clearHistory`） |
| `app/src/main.ts` | 抵扣式等待（`Math.max(0, 1000 - performance.now())`） |
| `app/index.html` | `#boot-splash .mark` 的呼吸动画 ＋ `prefers-reduced-motion` 兜底 |
| 三处版本号 | `app/package.json` / `tauri.conf.json` / `Cargo.toml` → `3.16` |

⚠️ **数据库零改动**（⛔ 不加字段、⛔ 不动 `SCHEMA_VERSION`）、**零新依赖**、**不用重编 tauri**。

## 四、这一轮踩到的两个坑（都值得留下）

### 1. ⭐⭐ 「用例没造成」⇒ 功能是对的、断言照样红

`P.45`（"清空只管历史、不动结果"）断言**搜索后结果数 > 0** ——
可 P 组开头**忘了先塞一篇含那个词的日记**，搜「柠檬」在真实的一次性库里就是 **0 条** ⇒ 红。
**症状极具误导性**：看着像"清空把结果也清掉了"，实际是**用例的前提根本不存在**。

**修法**：P.0 先塞两篇含「柠檬」「夜色」的日记，并让 `P.11` 顺手断言 `resultCount > 0`
（既是前提、也是断言）。**规则：凡断言"某动作之后某量 > 0 / 某状态变化"，第一步就要把那个量先造出来。**

### 2. ⭐⭐ 本机系统开着「减弱动态效果」⇒ 动画断言全假红

`Q.11` / `Q.12c` 要验启动画面图标在「呼吸」，结果 `animationName` 恒为 `none`、透明度恒为 1。
**根因不是代码** —— **本机 Windows 辅助功能里「减弱动态效果」是开着的**
（脚本探针实测 `{"减弱":true,"不减弱":false}`），而【P2-2】**本来就写了** `@media (prefers-reduced-motion: reduce) { animation: none }`
⇒ 系统一说"别动"，动画**按设计关掉**。

**修法（两件都得做）**：

1. 跑动画断言前，用 CDP 的 `Emulation.setEmulatedMedia` **显式把 `prefers-reduced-motion` 设成 `no-preference`**
   （⛔ 不能假定运行环境是"会动的"）；
2. 动画判据改用 **`getAnimations()` ＋ computed style**（拿 `animation-name` / `duration` / `iteration-count` / `playState`，
   **与帧率无关**），⛔ 不再只看"逐帧采样到透明度变化过" ——
   **验证是无头跑的，窗口一旦不可见，浏览器会把 rAF 节流到几乎不跑**（采样点不足 5 个）
   ⇒ "没采到变化"会被误判成"没有动画"。**采样点不足时该条不参与判定。**

⚠️ **两件事别混**：一个是"环境说了别动"，一个是"环境没空看" ——
**两个都会让同一批断言变红，别把其中一个的修法当成万能药。**

### 1. ⭐ 出安装程序（NSIS）

`发布\日记-3.16.0-安装程序.exe` —— **6,476,796 B / sha256 `4311BEEA…`**。

  （第 2.5 步 `tauri bundle -b nsis -f custom-protocol`，**只打包、不重编**）。
- ⭐ **为什么加 `-SkipBuild`**：本轮唯一被改的源码是**集成测试文件**（不进二进制）
  ⇒ 让安装程序**从「已经过 268 条界面校验的那一个 exe」打包**，
  ⛔ 不为了"重新构建"而产出一个**没验过的新二进制**。
- ⚠️ **与「不能加 `-SkipBundle`」不矛盾**：`-SkipBundle` 跳过的是**打 NSIS 包**（本次照打），
  `-SkipBuild` 跳过的是**重新编译**（本次该跳 —— 源码没动）。
- ✅ 结构校验（非侵入式；本机没有 7-Zip，卸包比对做不了）：
  PE 头 `MZ` ＋ `Nullsoft` 标记 ×2 ＋ UTF-16LE「日记」命中。

### 2. ⭐ 修掉一条「永远为真」的断言

`app/src-tauri/tests/vault_integration.rs::one_entry_per_day_is_enforced` 原来是
`assert_eq!(entry.created_at, entry.updated_at)`，注释写着"创建时间应保持第一次的值" ——
可这两个时间戳**都由 `now_iso()` 在同一次 `save_entry` 内部取，必然相等**
⇒ **那条断言永远为真、一个字节都没验**。

而且它还是个**假红源**：`updated_at` 会被下一次保存刷掉，两次保存**跨过 1 秒边界**就红
（`3.16` 跑全量时实测 `08:08:17Z` vs `08:08:18Z`；单独重跑又过 ⇒ 极易被当成"flaky 而已"）。

**改法**：第一次保存后先读一份基线 `first`，第二次保存后断言
`entry.created_at == first.created_at`（顺带钉住 `entry.id` 不变）。
**既真验到了语义、又不受秒边界影响。** 修完**复跑全量仍 219（120 ＋ 99）0 failed**。
