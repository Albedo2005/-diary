**⭐ 一个机制性的坑（比上面几条都重要）**

**"没被用到的后端命令，编译器永远不会报。"**
凡是登记进"命令表"的函数，编译器就认为"有人在用" —— **哪怕前端和它自己都不调**。
⇒ 这就是"命令表"会悄悄漂移的原因，**也是 P3-0（自动检查）真正的价值所在**。

**a) 按月取数 —— 入口曾定＝年轮页（⚠️ 2026-09-30 用户撤回，改挂起）**

- 后端给的是：**日期 / 标题 / 字数 / 心情 / 更新时间**。
- ⚠️ **一个必须先讲的背景**：日历**曾经用过它，后来故意拿掉了**（注释还留在日历文件里）。
  原因：它会把"表里有行"当成"写过"，**掩盖了"空草稿不算写过"这条过滤**。
  ⇒ 接回来时**只能当"月列表"用**，⛔ **绝不能拿它决定"哪天算写过"**。
- 怎么接线：取数与日历现有的两次并发查询**合在一起**（用同一个 `Promise.all`，
  **不再多发一次 IPC**）→ 存进新变量 → 模板里列出来。
- 怎么验：某月**写 2 篇 ＋ 留 1 个空草稿** ⇒ 列表**只出现 2 篇**（空草稿不算）；
  切月 ⇒ 列表跟着换；改标题 / 心情 ⇒ 回来列表跟着更新。
- ⏸ **2026-09-30 用户拍板：几种放法都不好 ⇒ 先挂起**，等后面哪个功能真用到再接（见功能列表「挂起」）。

**b) 列备份 —— 入口＝设置页「从备份恢复」那一行**（⇒ 归 P3-5）

- 后端给的是：**路径 / 字节 / 创建时间**（按时间倒序）；**目录不存在时返回空、不报错**。
- 入口在哪：【数据与备份】→「从备份恢复」。**现在是让用户手打整条路径**
  （占位符写着"例如 …\data\backups\diary-20260923-161500.db"）——
  这就是最典型的半成品：**后端能列，界面却要人背路径**。
- 怎么接线：进这个页签时列一次 → 渲染成一个列表，**点一份就把路径填进现有输入框**
  → 再点「恢复…」。✅ **手打路径那个入口原样保留**（是多一条路，不是替换）。
- 怎么验：先点「立即备份」造 1~2 份 ⇒ 列表出现 1~2 条、按时间倒序；

## 四、已定案的讨论存档

> 这些是**已经定了**的东西，从功能列表里搬过来留档 —— 免得清单被讨论过程撑乱。

### 4.1 「可扩展」是什么（原功能列表 2.2）

**一句话**：可扩展 ＝ **"以后想加东西时，要动的地方少，而且漏了会立刻发现"**。

它**不是**"把代码重写一遍"，而是解决**一个具体的疼**：

| 现在的疼 | 具体到什么程度 |
|---|---|
| **加一条新功能要改四个地方** | 有一处没改，**编译器不报错** —— 只是功能"悄悄不生效" |
| **最大的那个文件装了后端的三分之二** | 8,155 行；找一处 SQL 只能靠搜索 |
| **三个界面文件大到看名字猜不到内容** | 写日记那屏 2,896 行、设置页 1,954 行、主界面 1,616 行 |

**⚠️ 但有一条必须说清楚**：可扩展**本身不会让你看到任何新东西** —— 它只让"以后改起来便宜"。

### 4.2 方案①「只加自动检查」到底做什么（原功能列表 2.4）

**一句话**：写一个**离线脚本**，把「**后端登记的命令**」和「**前端能调的通道**」两张表**对一遍**，
对不上就**报红** —— 它只是**仓库里的一个工具**，⛔ **不进产品代码、不进安装包**
（你装的 `日记.exe` 里根本没有它）。

**① 检查哪些内容**（4 类，从最要紧到最松）

| 检查项 | 报什么 | 严重度 |
|---|---|---|
| 前端调了、后端**没登记** | "命令不存在，一运行就报错" | 🔴 **硬错误**（必须修） |
| 后端登记了、**谁都不调** | "这条命令是死的"（E1 那种） | 🟡 警告（多数要修，少数走白名单） |
| 前端封装了函数、**界面没人 import** | "功能做了一半"（E3 那 4 条） | 🟡 警告（可能是有意留的） |
| 命令名 / 文档里的名字**对不上** | 文档过期（D 组那种） | 🔵 提示 |

**② 触发时机**（建议挂三处 ＋ 一处"明确不做"）

| 时机 | 怎么挂 | 效果 |
|---|---|---|
| **手动** | 敲一条命令就跑（一个脚本） | 想查随时查 |
| **提交前** | 挂进提交流程，**不通过就不让提交** | 雷**在进仓库前**被拦下 |
| **发布前** | 打包脚本开头调一下，**红就不打安装包** | 雷**在出门前**被拦下 |
| ⛔ **不做** | **不在应用运行时检查** | 那是给用户装的东西，不该带开发期的检查 |

**③ 失败时怎么处理**

- 脚本**打印一张对照表**（哪条命令 / 哪类问题 / 在哪一行），并**以"失败"退出**。
- ⛔ **绝不自动改代码**：只报"哪里对不上"，**改不改、怎么改由人定**（有些是**故意**不接线的）。
- ⚠️ **能力边界**：它只能发现"**登记与调用对不上**"，**发现不了"逻辑写错"** —— 后者要靠测试。⇒ 它是**补丁**，**不是测试的替代品**。

**④ 不涉及哪些改动（这条最该看）**

| 不碰的 | 为什么 |
|---|---|
| ⛔ **产品代码** | 脚本在 `scripts\` 里，够不着 `app/src/**` |
| ⛔ **版本号** | 还是 `3.16` |
| ⛔ **发布件** | `日记.exe` **逐字节不变** —— 脚本根本不进安装包 |
| ⛔ **268 条界面验收** | 界面一行没动，不用重跑 |
| ⛔ **全量测试** | 产品代码没动，不用重跑 |
| ⛔ **新依赖** | 用现成的 Node / PowerShell 就够 |

✅ **唯一的产物**：仓库里**多一个脚本 ＋ 一份白名单 ＋ 一行使用说明**。

⚠️ **唯一的代价**：脚本要维护一份**"白名单"**（记下"这几条命令是**故意**不接线的"）。
但这**恰恰是好事**：不写进白名单，脚本就报红；写了，等于**留下一条"为什么"的记录**
—— 把"**悄悄漂移**"变成"**必须说明**"。

### 4.3 方案①的工程量评估（原功能列表 7.6）

**现成的有一个，但本机用不了 —— tauri-specta**：它从 Rust 每个命令**自动生成**前端要用的 TypeScript，
前端想调不存在的命令会**编译不过** ⇒ 等于**从根上消灭漂移**（比"事后检查"更彻底）。
- ⛔ **本机用不了**：它要给 Rust 加**新依赖**，而**本机 Rust 拉不到 crate（无网）**；
  且要把 **70 条命令全部改成另一种注册写法** ⇒ 那是"**大改**"。
- 除它之外，**没有**更轻的现成工具（Tauri 官方不带这种检查）。

**自己写：约 100~150 行**。有个现成便宜可占 —— 前端已有**零依赖的 Node 测试**（`pnpm test:fe`，原生跑 `.ts`），
所以这道检查可以**直接写成一个测试文件**，不用新造一套跑法。

| 要做的 | 大约 |
|---|---|
| 从后端注册表读出"命令名单" | ~20 行 |
| 从前端唯一出口读出"调了哪些" | ~20 行 |
| 从界面文件读出"哪些出口真被用了" | ~40 行 |
| 两两对比 ＋ 白名单 ＋ 打印 ＋ 失败退出 | ~40 行 |

### 4.4 「调间隔」≠「能退回」（原功能列表 7.4 的区分）

现在的"自动保存"是**正文改动后 1 秒落到库里**（防丢）。**它本身不产生"历史版本"。**
⇒ **即使把间隔调长，误删之后也照样退不回** —— 库里只存"最后一次"。

| 你想要的 | 实际要做的事 | 量 |
|---|---|---|
| **只是让"写盘不那么频繁"** | 把写死的 1 秒变成设置项（给几个档位） | 小 |
| **误删后能退回**（原话"想退回却没有办法"） | 要加一套**历史版本**：每次保存留一份旧的、定"留几份 / 留多久"、再加一个看历史的入口 | **大得多** |

✅ **2026-09-30 你已定：只调间隔**（不做历史版本）。

### 4.5 默认字体 / 字号 —— 两种理解（原功能列表 7.5）

编辑器顶部那两个框（字体 / 字号）是**按篇写进正文的排版标记** ——
是"**给这一段文字**用的"，不是"**给这个软件的默认值**"。

1. **默认值 / 全文替换 / 两个都要？**
   - **默认值** ＝ 新开一篇时编辑器一开始就用它（⚠️ 老日记一个字不动）
   - **全文替换** ＝ 加个按钮，把**当前这篇**整体换成这个字体字号
2. **要不要连"每行多少字"一起做？**
   代码注释里留了一句：**"每行 N 字"的设置必须复用现有那个行宽变量**（620px ≈ 38 字），⛔ 不许另立第二个。

⚠️ **必须守的底线**：字体 / 字号是**写进正文（存进库）的标记** ⇒
设成"默认"时**只能影响新写的和显式替换的**，⛔ **绝不能去改老日记的排版**。

### 4.6 每日字数目标疑点（原功能列表 7.3）

**你报的**：设置里设置了每天写 50 字，程序里并没有相对应的提示，只有一个 0 字。

**查的结果**：**代码链路是完整的**（设置框 → 后端 → 主界面 → 编辑器 → 底部那一句），**没有缺环**。
显示与否只看一个条件：**目标 > 0 且 正在看"今天"**。

⇒ 只可能是下面两种之一，**要你确认是哪一种**：

| 可能 | 说明 | 怎么试 |
|---|---|---|
| **① 你看的不是"今天"** | ⭐ **设计如此**：翻到旧日子还显示"0 / 50 字"，会被误读成"这天只写了 50 字"，所以**有意隐藏** | 切回**今天**那篇，看底部有没有变成「0 / 50 字」 |
| **② 那个框填完没提交** | 那个框是"**离开输入框才生效**"。填完**直接关掉设置弹窗**，可能没存上 | 重新填一次 → **按回车** → 关弹窗 → 回编辑器再看 |

⚠️ **没有当场复现，所以不猜是哪一种。** 你按上面两条各试一遍，把结果告诉我：

- 若是 **①** ⇒ **不用改**（是设计）；能做的只有"加一句提示"，但⚠️ 与"**界面不写解释性小字**"那条规矩冲突，要你定。
- 若是 **②** ⇒ 修法很小：把"离开才生效"改成"**边打字边生效**"或"**回车即生效**"。
