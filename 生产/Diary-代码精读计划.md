## 二、先记住五件事（这是第 1 批的内容，也是后面 11 批的地基）

### 2.1 四层数据流（一条单行道）

```
   ┌──────────────┐
   │  .vue 界面    │  用户看到、点到的
   └──────┬───────┘
          │  只能从这里出去（43 个函数，唯一出口）
   ┌──────▼───────┐
   │ api/index.ts │  前端唯一出口。任何 .vue 里都不许直接 invoke
   └──────┬───────┘
          │  跨进程边界（真正的前后端分界）
   ┌──────▼───────┐
   │ commands.rs  │  校验 + 守门（with_vault）。这里一行 SQL 都没有
   └──────┬───────┘
          │
   ┌──────▼───────┐
   │    db.rs     │  所有 SQL 只在这里
   └──────┬───────┘
          │
   ┌──────▼───────┐
   │ 加密的 .db    │  数据真正躺着的地方
   └──────────────┘
```

**看代码时的实用含义**：任何一个功能，你都能顺着这条线找到它的四段代码。
反过来，**如果你在 `.vue` 里看到 SQL、或在 `commands.rs` 里看到 SQL —— 那就是出错的地方**。

### 2.3 看一张表，永远问三个问题

这三问是**数据库设计的基本功**，比记字段名有用得多：

| 问 | 为什么重要 | 举例 |
|---|---|---|
| **① 主键是什么？** | 决定"一行怎么被唯一认出来" | `entry_tag` 用的是**复合主键** `(entry_id, tag_id)` —— 天然保证"同一篇里同一个标签不会出现两次" |
| **② 唯一约束是什么？** | 决定"什么情况下会插不进去" | `entry` 的 `UNIQUE(entry_date)` —— **一天一篇不是代码管的，是数据库管的** |
| **③ 外键指向谁？删了会怎样？** | 决定"删一个东西时，别的什么会跟着消失" | `entry_tag.tag_id → tag(id) ON DELETE CASCADE` —— **这就是为什么删标签必须做成软删除**（第 7 批详解） |

## 三、每批的固定"五步看代码法"

**这是你以后独立看任何一个功能都能用的方法**，比记代码有用。
**它的顺序 = 数据流的顺序** —— 顺着用户的一次点击，一路往下走：

| 步 | 看什么 | 文件 | 这时候该问自己的问题 |
|---|---|---|---|
| **1** | **界面** | `.vue` | 用户在屏幕上能看到什么、点什么？**它调了哪个函数？** |
| **2** | **接线** | `api/index.ts` | 那个函数叫什么名字？参数是什么？ |
| **3** | **命令层** | `commands.rs` | 入口怎么校验、怎么守门？是不是用 `with_vault` 包住了？ |
| **4** | **数据层** | `db.rs` 对应分区 | SQL 怎么写的？空数据 / 超范围怎么处理？ |
| **5** | **表** | `schema.rs` | 那些列到底长什么样？约束是什么？ |

> ⚠️ **第 5 步 `schema.rs` 不在数据流上** —— 它是一份"静态说明书"，不是流程里的一环。
> 排在最后，是因为前四步读下来你心里已经有"要查哪张表"了，这时候去核对列定义最有效。
> **别把它当成第 2 步。**（早先版本的这份文档里写错过一次 —— 用户 2026-09-22 抓出来的，已修正。）

**一个小验证**：这五步和 2.1 那张单行道图**方向完全一致**（`.vue → api → commands → db`），
唯一"不在路上"的就是第 5 步 —— 这也正是它能放到最后的原因。

**背下这五步。** 你以后看别人的项目也是这五步，只是文件名不一样。

> 📌 **例外**：**第 1 批（地图课）不按这五步走** —— 它是先横着把 7 张表和四层结构看一遍，
> 相当于"先看地图再上路"。第 2 批起才用五步法。

## 附：关于 `doLock()` 那处隐患

第 5 批会讲到。先记在这里免得忘：

**现象**：点「锁定」时，`App.vue` 是**先锁库、再让编辑器卸载**。而编辑器卸载时会自动保存（`onUnmounted` 里的
`flush()`），此时库已经锁了 → 保存必然失败 → **锁定前 1 秒内的编辑静默丢失**（自动保存防抖 1000ms）。

**修法**：`doLock()` 里改成**先落库、再锁**。

**状态**：⬜ **未修**。属于"数据丢失"类，但改的是既有代码，**等你决定**。
