生命树 · 风与花瓣 技术样张 · 零依赖 · 纯 SVG ＋ CSS · 不在项目里

环的粗细＝那种心情写过多少天；环从里往外＝从最早那档往最新那档排。 0 天的那档不画环，只在图例里写明 —— 画一圈看不见的线等于骗人。

借自：CSS 多重同心圆环（多层 border-radius:50% 叠圆／conic-gradient 切环形） 这一类做法。这里用 SVG 的 <circle> ＋ 不同 stroke-width， 比叠 div 更好控制（线宽是真的按数据算出来的，不是视觉凑的）。

风不是把整棵树一起摇 —— 是每一级枝条各自摇，而且周期都不同， 越靠梢头摆得越厉害。父枝动，子枝跟着动（坐标是叠着算的），这才是"风"而不是"晃动"。

花的直径按「倍数的平方根」长 —— 想让"看起来大 7 倍"真的是 7 倍那么大，半径就得开平方（面积感知）。
借自：SVG 递归分形树（枝条 ＝ 一条线，每一级继承上一级的坐标系再旋转、缩短）。 ⚠️ "摆动"这里没用 CSS，用的是 SMIL 的 animateTransform： CSS 的旋转中心得靠 transform-origin 指定，而它在 SVG 上默认参考"整块画布"， 实测对嵌套的 <g> 摆不正（整棵树会被甩出画面）；SMIL 直接写死旋转中心，反而干净。

每一片花瓣的起点、大小、下落时长、横飘距离、旋转圈数都是随机的， 但随机值只算一次，写进 CSS 变量里 —— 不是每帧用脚本去挪。

为什么不用纯 CSS 的 random()：网上那些"纯 CSS 随机花瓣"教程大多用了它， 但它目前的浏览器里根本还不支持（Chromium 计划到 155 版才上）。 照抄会直接跑不起来。正解就是这里的做法：随机数在 JS 里算一次，塞进 CSS 变量。
⚠️ 切到别的面板时，动画是"暂停"而不是"删掉" —— 不这样，你在写日记的时候它会在后台一直烧显卡。
